- (event) brief workspace created; discovery starting
- (idea by user) dashboard has multiple views: per-package Scorecard view, and Instrumentation (IL invocation) view can live alongside it
- (idea by user) project-level view needs a full transitive package overview with certain (TBD) information per dependency
- (decision by user) the Scorecard view component is shared/reused between the centralized hosted (cloud) dashboard and a local view
- (idea by user) the dashboard can also run in the context of a .NET project itself (not only as a separate hosted service)
- (idea by user) dashboard should surface data from other fennec CLI features too, not just scorecard/instrumentation
- (gap) need to determine a shared JSON structure/format for command results so both project-scoped (.fennec/ output) and hosted views can consume the same data
- (idea by user) that JSON output could possibly be committed into the source repo (not just gitignored cache) to enable the project-scoped dashboard / history
- (decision by user) v1 priority/scope: full transitive dependency tree for a project + Scorecard view, shipped first
- (insight) the real problem is audience/presentation fit, not detection risk: CLI/JSON output is well-suited to terminal workflows and LLM/agent consumption (ties to FennecLabs.Mcp, FD-013), but developers want a comprehensive, browsable view of the same data
- (idea by user) dashboard should be viewable in a browser AND natively inside tools like the GitHub Copilot App (canvas-style surface)
- (decision by user) primary audience spans both: developers wanting to understand their own project's dependencies, and application security engineers wanting a risk-based, org-wide view — both project-scoped and hosted modes serve both, at different scales
- (decision by user) differentiator = reach and usability, not a new data source: one dashboard, one shared data model, works locally and hosted without duplicating views
- (decision by user) v1 scope: project-scoped dashboard only (transitive dependency tree + Scorecard view), on a new shared/versioned JSON schema, possibly committed to the repo; hosted mode, Instrumentation/Compare/Reproduce views, auth/multi-tenant, and a Copilot App canvas surface are all deferred past v1
- (assumption) Vision (2-3 year horizon) intentionally left open — too early to say, per user
